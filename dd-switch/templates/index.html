📖 使用说明

这是什么：本地路由让 Claude Code 指向本机网关 http://127.0.0.1:9301，所有请求由 cc-switch-proxy 转发给当前供应商；客户端不再直连上游。

什么时候需要（仅这两种场景）

  • ① 转接口：上游不是 Anthropic 协议（如 OpenAI / Gemini 格式），由代理做协议转换，Claude Code 照常使用；或把多个上游统一成一个本机入口。
  • ② 加代理：出站请求需要经网络代理（HTTP / HTTPS / SOCKS5）才能到达上游——在本页「出站代理」一栏填入地址并保存（与桌面端全局代理同一份设置，也遵循 HTTP_PROXY 等环境变量），写入后需重启路由生效。

只是直连 Anthropic 协议供应商、网络通畅的话，用原来的切换流程直连即可，不必开本地路由。

使用步骤

  • ① 添加或导入供应商：点「添加供应商」手工填写，或「从本机导入」选择浏览设备上的配置文件；选一个作为当前供应商。
  • ② 开启路由：dd-switch 拉起本机 cc-switch-proxy 进程（仅回环 127.0.0.1:9301，普通子进程，不是服务），同时把 Claude Code 指向网关。

模型名由用户负责：在 Claude Code 的 settings.json 里写真实上游模型名（如 "ANTHROPIC_DEFAULT_OPUS_MODEL": "hy4-preview[1M]"），面板只指向网关，不再代写档位别名。请求里的模型名若命中该供应商的模型路由表，就按表走对应节点与接口形态；未命中走默认接入点与协议。

注意

  • 仅服务本机（127.0.0.1）；通过 SSH 管理的远程服务器不参与路由。
  • 路由开启期间不能切换配置档；点「关闭路由」会自动恢复原配置并结束进程。
  • 代理不会随重启自动拉起；重启主机后在面板再点一次「开启路由」，会复用已有快照。
  • 需要登录授权的供应商（GitHub Copilot、ChatGPT/Codex、xAI）只能在 cc-switch 桌面端使用；无界面守护进程只支持 API Key 类供应商。
  • 运行该二进制需要 WebKitGTK/GTK 运行库；编译与运行依赖说明见 README「本地路由」一节与 patches/README.md。
